# 05 · 常见报错与排查手册

> 用法：先看**现象**找到对应编号，再对照**报错原文**确认，然后按**怎么改**操作。
> 通用思路：**先分清是"请求没发出去"还是"发出去了但结果不对"** —— 看 Network 面板里的状态码。

---

## 快速定位流程图

```
页面没数据 / 报错
      │
      ├─ 控制台红色带 "CORS"        → 【01】跨域
      ├─ 控制台红色带 "Failed to fetch"
      │   或 "ERR_CONNECTION_REFUSED" → 【02】后端没启动
      ├─ Network 里 Status = 404     → 【03】地址写错
      ├─ Network 里 Status = 400/500 → 【04】数据格式问题
      ├─ 请求 200 但表格还是空       → 【05】渲染问题
      ├─ db.json 里没有新增的数据    → 【06】没写进去
      └─ 命令窗口报错，服务起不来    → 【07】【08】
```

---

## 【01】跨域 CORS 报错 ⭐ 最高频

**现象**：点击按钮后表格空空如也，控制台一片红色。

**报错原文**：

```
Access to fetch at 'http://localhost:3000/goods' from origin 'null'
has been blocked by CORS policy
```

**原因**：页面是用 `file://` 协议打开的（双击 html 文件），浏览器认为来源不可信，拦住了请求。

**怎么改**：

1. 关掉这个页面
2. 在 VS Code 里右键 `index.html` → **Open with Live Server**
3. 确认地址栏变成 `http://127.0.0.1:5500/...`
4. 再点一次按钮 → 数据出来了

**记住**：不是代码错了，是**打开方式**错了。

---

## 【02】连不上后端：Failed to fetch ⭐ 高频

**现象**：控制台报错，Network 里请求状态是 `(failed)`。

**报错原文**：

```
TypeError: Failed to fetch
GET http://localhost:3000/goods net::ERR_CONNECTION_REFUSED
```

**原因**（按概率排）：

| 概率 | 原因 | 检查方法 |
|:-:|:---|:---|
| 60% | json-server 黑窗口被关了 | 看有没有那个黑窗口 |
| 20% | 在错误的文件夹里启动的 | 窗口标题/路径是不是 `mock-goods` |
| 15% | 端口号不一致 | 代码写 3000，启动时用了 4000 |
| 5% | 服务还在启动中 | 等几秒再刷新 |

**怎么改**：回到 `mock-goods` 文件夹，重新执行

```bash
npx json-server --watch db.json --port 3000
```

然后确认代码里的地址是 `http://localhost:3000/goods`。

## 【03】404 Not Found

**现象**：请求发出去了，但状态码是 404。

**原因**：接口地址写错了。json-server 的地址来自 db.json 里的**顶层 key**。

```json
{
  "goods": [ ... ]        ← 这里叫 goods，接口就是 /goods
}
```

**常见错误对照**：

| 错误写法 | 正确写法 |
|:---|:---|
| `http://localhost:3000/good` | `.../goods` |
| `http://localhost:3000/api/goods` | `.../goods` |
| `http://localhost:3000/goods` 但 db.json 顶层是 `products` | 改成 `/products` |

**怎么改**：先直接在浏览器地址栏访问 `http://localhost:3000`，页面上会列出所有可用资源名，照抄即可。

---

## 【04】400 / 500：数据格式问题

**现象**：POST 提交后报错，或数据存进去了但内容不对。

**原因 1：漏了 Content-Type**

```javascript
// ❌ 错误
fetch(url, { method: 'POST', body: JSON.stringify(data) })

// ✅ 正确
fetch(url, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(data)
})
```

**原因 2：漏了 JSON.stringify**

```javascript
// ❌ 错误：发出去的是 [object Object]
fetch(url, { method: 'POST', body: data })

// ✅ 正确
fetch(url, { method: 'POST', body: JSON.stringify(data) })
```

**原因 3：db.json 语法错误**

- 多了一个逗号
- 键名用了单引号
- 最后一个元素后面还留着逗号

**怎么改**：把 db.json 内容粘到 https://jsonlint.com 检查，或者看 json-server 窗口的报错提示。

## 【05】请求成功（200）但表格没东西

**现象**：Network 里能看到数据返回了，页面上还是空白。

**原因**（按概率排）：

| 原因 | 检查点 |
|:---|:---|
| 没调用 `render()` | `loadGoods` 里有没有 `render(goodsList)` |
| 元素没选到 | `document.querySelector('#table-body')` 里的 id 和 html 里的对不对 |
| script 引入失败 | `<script type="module" src="./main.js">` 路径对不对 |
| 数据不是数组 | 控制台打印一下 `data` 看看结构 |

**排查口诀**：

```javascript
console.log('1. 数据拿到了吗：', goodsList)
console.log('2. 元素找到了吗：', tableBody)
console.log('3. render 调用了吗：', '在 render 里加一行 console.log')
```

## 【06】db.json 没有新增的数据

**现象**：POST 提示成功，刷新页面也能看到，但 db.json 文件里没有。

**原因**：

1. 你看的是**另一个文件夹**里的 db.json（最常见！）
2. 文件被编辑器缓存了，点一下文件刷新
3. json-server 是从**别的目录**启动的

**怎么改**：看 json-server 窗口里 `Loading db.json` 上面显示的完整路径，去那个路径找。

---

## 【07】端口被占用：EADDRINUSE

**报错原文**：

```
Error: listen EADDRINUSE: address already in use :::3000
```

**原因**：3000 端口已经被另一个 json-server 占了（通常是上次的窗口没关干净）。

**怎么改**（任选一）：

```bash
# 方案 1：换个端口
npx json-server --watch db.json --port 4000

# 方案 2：关掉所有 json-server 窗口再重启
```

> 换端口后，代码里的地址也要改成 `http://localhost:4000/goods`。

---

## 【08】db.json 格式错误，服务起不来

**报错原文**：

```
SyntaxError: Unexpected token } in JSON at position 123
```

**原因**：JSON 语法错误。

**常见错误**：

```json
{
  "goods": [
    { "id": 1, "title": "鼠标", },     ← ❌ 最后一个字段多了逗号
  ]                                     ← ❌ 数组最后多了逗号
}
```

**怎么改**：删掉多余的逗号，或用 https://jsonlint.com 校验。

---

## 【09】npx 下载慢 / 卡住

**现象**：`npx json-server` 执行后半天没反应。

**原因**：默认从国外 npm 源下载。

**怎么改**：

```bash
# 临时用国内镜像
npx --registry=https://registry.npmmirror.com json-server --watch db.json --port 3000

# 或者永久切换
npm config set registry https://registry.npmmirror.com
```

---

## 【10】端口不一致（隐性错误）⭐ 很坑

**现象**：后端在 3000，前端 Live Server 在 5500，代码里却写的是 8080。

**排查**：三处必须完全一致

```
① json-server 启动命令：  --port 3000
② 浏览器验证地址：        http://localhost:3000/goods
③ 代码里的 baseUrl：      'http://localhost:3000/goods'
```

---

## 【11】fetch 的 404/500 不进 catch ⭐ 与 Axios 的关键差异

**现象**：接口返回 404，但 `.catch()` 没执行，代码继续往下跑。

**原因**：fetch 只在**网络彻底失败**时才进 catch；404 / 500 在 fetch 看来属于"服务器有回应"，所以算成功。

**怎么改**：

```javascript
const res = await fetch(url)
if (!res.ok) {                        // res.ok 只在 200–299 时为 true
  console.error('请求失败，状态码：', res.status)
  return                              // 提前结束，别往下走
}
const data = await res.json()
```

> 这也是 Axios 更好用的地方之一：它会自动把 404/500 丢进 catch。

---

## 【12】改了 db.json 但接口数据没变

**原因**：启动时漏了 `--watch` 参数。

**怎么改**：

```bash
# ✅ 正确（带 --watch，改文件自动生效）
npx json-server --watch db.json --port 3000

# ❌ 错误（不带 --watch，只在启动时读一次）
npx json-server db.json --port 3000
```

## 万能排查四步（教给学生）

```
① F12 → Console：读红色报错，关键词是 CORS / 404 / 500 / Failed
② F12 → Network：看 Status 是几，看 Response 里返回了什么
③ 检查三处一致：端口、地址、字段名
④ 还是不行 → 报错 + 代码一起粘给 AI
```

## 问 AI 的正确姿势

❌ **不好**："我的代码报错了怎么办"

✅ **好**：

```
我是前端初学者。下面是我控制台的报错和出问题的代码：

【报错】TypeError: Failed to fetch
【代码】const res = await fetch('http://localhost:3000/goods')
【背景】我用 json-server 启动了后端，用 Live Server 打开页面

请告诉我：哪里错了、为什么、怎么改。
```

# 06 · AI 提示词模板（第9周 · 接口交互专题）

> 承接第 8 周提示词工程。本周 AI 只用在三件事上：**生成 Mock 数据、写接口文档、辅助排错**。
> 红线：**AI 给的代码必须自己读懂**，课堂上会随机抽人解释任意一行。

---

## 提示词三件套（每次都带上）

```
【角色/背景】我是前端初学者 / 我在学什么
【任务】要 AI 做什么
【约束】输出格式、代码长度、不要什么
```

---

## 模板 1：生成 Mock 数据

### 基础版（课堂用）

```
帮我生成 json-server 用的 db.json，资源名称是 goods，
字段：id(数字自增)、title(商品名称)、price(价格)、stock(库存)。
生成 10 条真实感的数码商品数据，输出纯 JSON，不要任何多余文字和解释。
```

### 进阶版（换主题）

```
帮我生成 json-server 的 db.json，资源名 students，
字段：id、name(中文姓名)、age(18-22)、major(专业)、score(60-100)。
生成 15 条数据，输出纯 JSON，不要解释文字。
```

### 带约束版（造边界数据）

```
帮我生成 json-server 的 db.json，资源名 goods，
字段：id、title、price、stock。
生成 12 条数据，其中要包含：2 条库存为 0 的、
2 条价格大于 1000 的，用来测试页面显示。
输出纯 JSON。
```

> ⚠️ **必查**：AI 输出常带 ` ```json ` 代码块标记，只复制花括号 `{ }` 内的内容。

## 模板 2：生成接口文档

### 基础版

```
基于 json-server 的 goods 资源，帮我写一份简洁的接口文档，
包含：请求方式、URL、请求参数、返回示例。
面向前端开发，要能直接照着调，不要写后端实现细节。
```

### 表格版（更好用）

```
基于 json-server 的 goods 资源，帮我用表格写一份接口文档，
每行包含：接口名称、请求方法、URL、请求参数、请求体示例、返回示例、说明。
至少包含：查询列表、查询单条、新增、修改、删除 五个接口。
```

## 模板 3：调试接口报错 ⭐ 最实用

```
我是前端初学者，我的代码报错了。

【报错信息】
（粘贴控制台红色文字）

【我的代码】
（粘贴相关代码）

【背景】
我用 json-server 在 localhost:3000 启动了后端，
用 VS Code 的 Live Server 打开了页面。

请告诉我：
1. 错在哪里（指出具体行）
2. 为什么要这样写才对
3. 改好的完整代码
```

## 模板 4：生成请求代码

```
帮我写一段原生 fetch 的代码，实现：
- 从 http://localhost:3000/goods 获取商品列表
- 渲染到 id 为 table-body 的 tbody 里
- 每行显示 id、title、price、stock
要求：用 async/await 写法，加中文注释，代码不超过 40 行。
```

## 好提示词 vs 坏提示词（课堂对比用）

| 场景 | ❌ 坏提示词 | ✅ 好提示词 |
|:---|:---|:---|
| 造数据 | "给我一些商品数据" | "生成 json-server 的 db.json，资源名 goods，字段 id/title/price/stock，10 条数码商品，纯 JSON 无解释" |
| 排错 | "代码报错了咋办" | "我是初学者，报错 [原文]、代码 [代码]、背景 [json-server+Live Server]，请指出错误行、原因、完整改法" |
| 写代码 | "写个请求" | "用 async/await 写 fetch GET 请求，渲染到 #table-body，加中文注释，不超过 40 行" |

**差别在哪**：好提示词给了**背景、格式、长度、约束**四样东西。

## AI 使用红线（课堂强调）

1. **不能不看就复制** —— 复制前必须能说出每一行在干什么
2. **AI 会一本正经地编造** —— 编造不存在的接口、编造错误的字段名，必须自己验证
3. **报错信息要原件粘** —— 不要自己转述，转述会丢失关键信息
4. **AI 给的答案要验证** —— 每次改完必须刷新页面、看控制台确认
